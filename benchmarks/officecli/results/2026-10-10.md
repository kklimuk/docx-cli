# Word task comparison — October 10, 2026

Across six Word tasks repeated three times, **docx-cli 0.27.0 and the Anthropic docx skill each received 18/18 task-success judgments; OfficeCLI 1.0.156 received 14/18**. All 54 outputs opened in Microsoft Word. docx-cli used fewer tool calls and tokens on average than either alternative in this run set.

This is a project-run comparison on an existing development corpus, using a model judge that knew the tool under test. It measures these tasks and tool snapshots, not general Office capabilities.

## What the grades include

- **docx-cli:** all 18 outputs were judged to preserve formatting and have sound layouts. That does not mean the tool was frictionless: the first redlining run exposed a Markdown read-view gap for lower-roman numbering, and reviewers noted minor issues such as choppy revision balloons. The earlier NDA-size and journal-pagination defects were not flagged in this batch; that alone does not prove their underlying causes were fixed.
- **Anthropic skill:** all 18 tasks passed with sound layouts. One résumé output was still marked formatting-degraded because date/location tab stops formed a ragged column. Two authored journals used `n/a` for formatting preservation because there was no source document to preserve.
- **OfficeCLI:** all three résumé attempts were partial with unsound layouts; dates and locations wrapped awkwardly, including mid-word. The first invoice attempt was partial because the new Notes text was inserted into a small spacer paragraph while the original Notes body remained. The other two invoice attempts passed. Four outputs were marked formatting-degraded.

The task-success and visual-quality fields are distinct judgments. We retain the returned grades and publish the defects alongside them rather than reclassifying outcomes after seeing the scores.

## Metric definitions and limits

Tool calls and tokens count exercise agents only; staging, rendering, judging, and synthesis are excluded. A Bash tool call can contain multiple shell commands. Input usage is deduplicated by API message ID. The **effective-input proxy** is fresh input + 1.25 × cache-write input + 0.1 × cache-read input. It is not a measured dollar cost. Fresh, cache-write, and cache-read counts remain separate in the JSON data.

Output counts use the collector's larger value of reported usage or its emitted-content estimate when streaming records lack final usage. **Cumulative task time sums the six agent durations**; it is not elapsed batch time, and concurrency and machine load can affect it. Means and ranges are calculated before display rounding.

The corpus has informed docx-cli development, and judges knew the tool under test. Three repetitions of six tasks do not establish statistical significance or broad superiority. A holdout corpus and blinded human review would support stronger claims. Do not compare token totals directly with earlier experiments using different builds, task snapshots, or measurement conditions.
