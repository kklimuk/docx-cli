# Word regression comparison — 2026-10-08

Historical result. The README now uses the [October 10 three-tool comparison](2026-10-10.md); the measurements below remain unchanged.

On six existing Word regression tasks, repeated three times per tool, the model judge marked **18/18 docx-cli tasks** and **13/18 OfficeCLI tasks** successful. All 36 outputs rendered in Microsoft Word. Success did not mean defect-free: docx-cli had one formatting defect and one layout defect among its passes.

This is a project-run comparison on a corpus that has informed docx-cli development. It measures these Word tasks and versions; it is not an independent evaluation of general Office capabilities.

[Per-task verdicts, metrics, and input hashes](2026-10-08.json) · [Protocol and reproduction steps](../README.md)

- The documentation branch was subsequently rebased onto main `47f0f3f` on October 9. These measurements retain the original frozen build and have not been relabeled as results for the rebased code. A minimal reproduction on `47f0f3f` still exhibits the NDA font-size readback defect.
- OfficeCLI: release [`v1.0.155`](https://github.com/iOfficeAI/OfficeCLI/releases/tag/v1.0.155), source commit `8d079c777ed6bea35b922c3d893758d3c2081137`, release-checksum-verified binary and matching native skills. Auto-updates disabled; normal resident behavior retained.
- Six tasks: NDA filling, invoice editing, résumé styling, contract redlining, review finalization, and journal authoring. Each repetition started from pristine inputs. One run per tool executed concurrently in each of three batches.
- All 57 frozen-input checks passed. OfficeCLI's source tree remained unchanged. No exercise had a relayed launch request or detected cross-scenario access. No exercise was rerun or its output repaired within this reported batch.

### Defects behind the counts

- **docx-cli r1, NDA:** signature values rendered at 12pt after the agent cleared their explicit 9pt size. The read view omitted the inherited 12pt size beneath an 8pt document-base hint, concealing the visual difference. The supplied values and document structure were correct.
- **docx-cli r2, journal:** two verse lines spilled onto an otherwise empty page 3, followed by the colophon on page 4. Required document features were present, but the pagination was poor.
- **OfficeCLI, résumé in all three runs:** locations and dates wrapped awkwardly, including mid-word breaks, rather than aligning cleanly at the right edge.
- **OfficeCLI, invoice in r1 and r3:** the judge marked incomplete or degraded edits; r1 inserted the new Notes text into a small spacer paragraph and left the original Notes body beneath it. See the data file for both full verdicts.

## Reporting correction and limits

The initial collector selected agents by model alone, accidentally including staging and rendering agents that also used Haiku. Reporting was corrected to select `exercise:<scenario>` metadata first, with a regression test. Usage is deduplicated by API message ID. Every corrected run contains exactly six distinct exercises. This changed reporting only; frozen exercises, prompts, binaries, and rubrics were unchanged. The data file records the corrected collector hashes.

The judges knew the tool under test; the rubric and corpus were developed in this repository. Three repetitions of six familiar tasks do not establish broad superiority or statistical significance. A holdout corpus and blinded human review would be needed for stronger claims.

Raw documents, Word renders, original and corrected reports, workflow returns, and transcript copies are retained locally under `tmp/comparison-20261008/`. The checked-in data file contains the per-task verdicts and corrected metrics; the full artifact bundle has not been published. Earlier interrupted or input-drifted attempts are excluded from this batch.
